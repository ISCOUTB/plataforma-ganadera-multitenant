📝 FLUJO COMPLETO DE UNA SOLICITUD DE IA
═══════════════════════════════════════════════════════════════════════════════

Chat con Llama 3B:

1. Frontend envía mensaje
   ↓
2. NestJS valida JWT + tenant_id
   ↓
3. NestJS llama: POST http://localhost:8000/chat/completions
   ↓
4. Backend IA Proxy recibe solicitud
   ├─ Registra: tenant_id en logs
   ├─ Valida: API keys configuradas
   ↓
5. Backend IA Proxy → HTTP POST a Groq Cloud
   ├─ Headers: Authorization: Bearer gsk_...
   ├─ Body: {"model": "mixtral...", "messages": [...]}
   ↓
6. Groq ejecuta Llama 3B (< 100ms)
   ↓
7. Backend IA Proxy recibe respuesta
   ├─ Extrae texto
   ↓
8. NestJS devuelve al Frontend
   ↓
9. Frontend muestra respuesta

⏱️ Total: ~300-500ms


🔒 SEGURIDAD MULTITENANT
═══════════════════════════════════════════════════════════════════════════════

✅ Protecciones implementadas:

  1. JWT Validation
     - Todo request requiere JWT válido
     - tenant_id extraído del token

  2. Tenant Scoping
     - NestJS filtra datos POR tenant
     - No se comparten datos entre fincas

  3. Data Isolation
     - Series temporales scoped a tenant
     - PostgreSQL valida pertenencia

  4. Audit Logging
     - Cada solicitud registra: tenant_id, user_id, timestamp
     - Logs almacenados en Backend IA Proxy

  5. Inference Only
     - NUNCA entrenamos con datos de otros tenants
     - Chronos-2 es pre-trained (sin reentrenamiento)
